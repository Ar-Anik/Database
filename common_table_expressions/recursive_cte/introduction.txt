Q : Recuresive CTE কী?
-> সাধারণ CTE একটি temporary result set তৈরি করে যা শুধুমাত্র একটি কুয়েরির মধ্যে ব্যবহার করা যায়। কিন্তু Recursive CTE নিজেকে
বারবার reference বা call করতে পারে যতক্ষণ না একটি নির্দিষ্ট শর্ত পূরণ হয়। এটি মূলত দুটি প্রধান অংশ নিয়ে গঠিত Anchor Member এবং
Recursive Member, এই দুটি অংশকে UNION বা UNION ALL দিয়ে যুক্ত করা হয়। Like :

WITH RECURSIVE cte_name AS (
    initial_query  -- anchor member
    UNION ALL
    recursive_query -- recursive member that references to the CTE name
)
SELECT * FROM cte_name;


# Syntax :
WITH RECURSIVE cte_name AS (
    SELECT initial_columns FROM table_name WHERE condition

    UNION ALL

    SELECT recursive_columns
    FROM table_name
    INNER JOIN cte_name ON table_name.id = cte_name.parent_id
)
SELECT * FROM cte_name;


SQL Engine `WITH RECURSIVE` Keyword দেখার পর পুরো query-কে দুই ভাগে ভাগ করে:
- Anchor Member: UNION বা UNION ALL-এর ঠিক উপরে থাকা কুয়েরিটি হলো Anchor Member। এটিই প্রথম রান হয়।
- Recursive Member: UNION বা UNION ALL-এর নিচে থাকা কুয়েরিটি হলো Recursive Member। এর ভেতরে CTE-এর নিজের নাম ব্যবহার করা
হয় যা engine-কে জানায় যে এটি একটি লুপ।

Database Engine (যেমন: InnoDB) যখন একটি Recuresive CTE Process করে তখন Memory-তে দুটি অস্থায়ী table বা বাফার ব্যবহার করে:
- Intermediate Result Table (Work Table): এখানে শুধুমাত্র আগের ধাপের বা বর্তমান iteration-এর data থাকে।
- Final Accumulator Table: এখানে শুরু থেকে শেষ পর্যন্ত পাওয়া সকল data জমা করা হয়।


-> Recursive CTE-এর Step by Step Workflow :
Step-1: Database Engine প্রথমে Anchor Member run করে। এর result সরাসরি Final Accumulator Table-এ পাঠানো হয় এবং একই সাথে Work
Table-এ জমা করা হয়।

Step-2: Database Engine এবার Recursive Member Run করে। এই কুয়েরিটি যখন CTE-কে call করে সে তখন main table(physical table, anchor
member যেখান থেকে data fetch করে) দেখে না বরং Work Table-এ থাকা data-গুলোকে input হিসেবে নেয়।

Step-3: Recursive Member থেকে নতুন যেসব data (Rows) পাওয়া যায়, সেগুলো Final Accumulator-এ যোগ করা হয়। এরপর পুরনো Work Table মুছে
ফেলে নতুন পাওয়া row-গুলো দিয়ে তা update করা হয়।

Step-4(Termination): এই প্রক্রিয়াটি ততক্ষণ পর্যন্ত চলতে থাকে যতক্ষণ না Recursive Member কোনো নতুন ডাটা খুঁজে পায়। অর্থাৎ যখন Work Table ফাঁকা
বা Empty হয়ে যায় তখন লুপ বন্ধ হয়।


# Example
WITH RECURSIVE cte_count AS (
    SELECT 1 AS n
    UNION
    SELECT n+1
    FROM cte_count
    WHERE n < 3
) SELECT * FROM cte_count;

Here,
- Anchor Member: SELECT 1 AS n
- Recursive Member: SELECT n+1 FROM cte_count WHERE n < 3

Step-1: Anchor Member run (Initial Step)
Database Engine প্রথমে SELECT 1 AS n কুয়েরিটি রান করে।
- Output: 1
- Work Table: এখানে 1 জমা হয়।
- Result Accumulator: এখানেও 1 জমা হয়।

Step-2: First Iteration
এবার Recursive Member run হয়। এটি Work Table থেকে data input হিসেবে নেয়।
- Input (n): 1 (Work Table থেকে পাওয়া)
- Condition Check: 1 < 3 ? Answer: True
- Calculation: 1 + 1 = 2
- নতুন মান 2 এখন Result Accumulator-এ যোগ হয় এবং পুরনো Work Table মুছে ফেলে সেখানে শুধু নতুন মান 2 রাখা হয়।

Step-3: Second Iteration
Recursive Member আবার run হয়। এবার সে Work Table-এ থাকা সর্বশেষ মানটি দেখে।
- Input (n): 2 (Work Table থেকে পাওয়া)
- Condition Check: 2 < 3? Answer: True
- Calculation: 2 + 1 = 3
- নতুন মান 3 এখন Result Accumulator-এ যোগ হয় এবং Work Table update হয়ে 3 হয়।

Step-4: Third Iteration and Termination
Recursive Member আবার run হয়।
- Input (n): 3 (Work Table থেকে পাওয়া)
- Condition Check: 3 < 3? Answer: False
- Calculation: যেহেতু শর্ত পূরণ হয়নি তাই এই query কোনো data return করে না (Empty Set)।
- Termination: যখন Recursive Member কোনো data return করে না তখন Database Engine বুঝে নেয় loop শেষ।

Loop শেষ হওয়ার সাথে সাথে Database Engine Work Table-টি memory থেকে delete করে দেয় এবং শুধুমাত্র Result Accumulator-এর ডাটাগুলো
user-কে return করে।

# Result:
1
2
3


-> Recursive Member-এর ভেতর কোনো ধরনের Aggregate Functions ব্যবহার করা  যায় না, like : MAX, MIN, SUM, AVG, COUNT etc
কারণ Recursive Member প্রতিটি ইটারেশনে শুধুমাত্র একটি নির্দিষ্ট row নিয়ে কাজ করে। Aggregate Function পুরো result সেটকে একটি মানে রূপান্তর করে
ফেলে, যা Recursion লজিকের সাথে সামঞ্জস্যপূর্ণ নয়।

-> GROUP BY, ORDER BY, LIMIT clause গুলো Recursive মেম্বারের ভেতরে ব্যবহার করা যাবে না

-> Recursive মেম্বারের FROM ক্লজে CTE-এর নাম শুধুমাত্র একবারই ব্যবহার করা যাবে। অর্থাৎ একই লুপে একাধিকবার CTE-কে call করা যাবে না।

-> CTE-এর নাম কোনো Subquery-এর ভেতরে ব্যবহার করা যাবে না। এটি সরাসরি FROM ক্লজের সাথে যুক্ত থাকতে হবে।

# Example :
WITH RECURSIVE PriceCountdown AS (
    SELECT MAX(total_amount) AS current_val
    FROM (
        SELECT customer_id, SUM(amount) AS total_amount
        FROM orders
        GROUP BY customer_id -- এখানে Group By অনুমোদিত
    ) AS summary

    UNION ALL

    SELECT current_val - 100
    FROM PriceCountdown
    WHERE current_val > 100 -- লুপ থামানোর শর্ত
)
SELECT * FROM PriceCountdown;
