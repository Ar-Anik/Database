-> A surrogate key is a type of primary key in a database that has no business meaning and is used solely to uniquely
identify each row in a table. Unlike natural keys (like email, SSN, or product code), a surrogate key is typically
generated by the database system and is not derived from the actual data.

# Key Points:
- Artificial / System-Generated: Surrogate keys are created automatically, usually as sequential numbers.
- No Business Meaning: They don’t carry any information about the entity; their sole purpose is uniqueness.
- Immutable: They don’t change even if the real-world data changes.
- Simplifies Relationships: Useful in foreign key relationships because they are simple, stable, and consistent.

# Suppose we have a Customers table:
------------------------------------------------------------------
| CustomerID | Name  | Email                                     |
| ---------- | ----- | ----------------------------------------- |
| 1          | Alice | [alice@email.com](mailto:alice@email.com) |
| 2          | Bob   | [bob@email.com](mailto:bob@email.com)     |
------------------------------------------------------------------

Here, CustomerID is a surrogate key. Names and emails are real-world data, but CustomerID just uniquely identifies
each row.

-> Surrogate Key in MySQL
MySQL can generate surrogate keys. The most common ways:

1. Using AUTO_INCREMENT:
CREATE TABLE Customers (
    CustomerID INT AUTO_INCREMENT PRIMARY KEY,
    Name VARCHAR(50),
    Email VARCHAR(100)
);

Here, CustomerID is a surrogate key. MySQL automatically increments it for each new row.

2. Using UUID (universally unique identifier):
CREATE TABLE Orders (
    OrderID CHAR(36) PRIMARY KEY,
    CustomerID INT,
    OrderDate DATE
);

INSERT INTO Orders (OrderID, CustomerID, OrderDate)
VALUES (UUID(), 1, '2025-10-03');

UUID() generates a globally unique surrogate key.


Q: CustomerID is auto-generated by the database. It’s often used for reading, searching, joining tables, etc. But does
this mean it’s a surrogate key?
-> Yes, because:
- It’s meaningless to business logic (CustomerID 1 doesn’t mean anything outside the database).
- It’s stable and guaranteed unique within the table.
