Pessimistic Locking হলো একটি concurrency control mechanism যা এই ধারণার উপর ভিত্তি করে কাজ করে যে, যখন একাধিক user বা process
একই সময়ে একটি resource access করে, তখন ডেটার Incompatibility or conflict হওয়ার সম্ভাবনা অনেক বেশি থাকে।

Pessimistic Locking-এর মূল ধারণা হলো কোনো resource ব্যবহারের আগে সেটির ওপর আগেভাগেই lock acquire করা। একটি transaction বা
critical operation চলাকালীন সেই resource-এর উপর exclusive access বজায় রাখা হয়। এর ফলে lock release না হওয়া পর্যন্ত অন্য কোনো
user বা process সেই resource-টি পরিবর্তন বা access করতে পারে না।

-> Feature of Pessimistic Lock
1. Acquiring Locks Upfront: কোনো resource-এ read বা write operation শুরু করার আগেই এটি lock অর্জন করে, যাতে অন্য concurrent
transaction সেটি access করতে না পারে।

2. Exclusive Access: একবার lock acquire হয়ে গেলে, এটি সেই transaction-কে সংশ্লিষ্ট resource-এর উপর exclusive access প্রদান করে।
lock release না হওয়া পর্যন্ত অন্য transaction গুলোকে wait করতে হয়।

3. Potential for Waiting: যেহেতু একটি transaction সম্পূর্ণ শেষ না হওয়া পর্যন্ত lock ধরে রাখা হয়, তাই High concurrency ক্ষেত্রে অন্য প্রসেসগুলোর
জন্য waiting time বেড়ে যেতে পারে।

4. Different Granularities: Pessimistic Locking database-level, table-level, row-level এমনকি column-লেভেলেও প্রয়োগ করা সম্ভব।


-> Advantages
1. এটি ডেটার Consistency নিশ্চিত করে, কারণ একাধিক process একই সময়ে data পরিবর্তন করতে পারে না।
2. Concurrent access manage করার জন্য এটি একটি অত্যন্ত সহজ এবং সরাসরি পদ্ধতি।

-> Disadvantages
1. High concurrency ক্ষেত্রে resource নিয়ে প্রতিযোগিতা এবং waiting time বৃদ্ধি পেতে পারে।
2. দীর্ঘ সময় ধরে lock ধরে রাখলে system-এর performance এবং throughput ক্ষতিগ্রস্ত হতে পারে।


-> Pessimistic Locking Use Case
1. High Contention
যে সকল ক্ষেত্রে ডেটার conflict ঘটার সম্ভাবনা অত্যন্ত বেশি থাকে, যেমন banking system যেখানে অত্যন্ত গুরুত্বপূর্ণ transaction পরিচালনা করতে
হয়, সেখানে Pessimistic Locking ব্যবহারের প্রয়োজনীয়তা অনস্বীকার্য। এটি নিশ্চিত করে যে একটি নির্দিষ্ট resource বা row-এর ওপর শুধুমাত্র একটি
process-এর exclusive access থাকবে। এর ফলে একাধিক সেশনের মধ্যে conflict-এর হার উল্লেখযোগ্যভাবে কমে যায় এবং data integrity
বজায় থাকে। যখন একটি transaction কোনো রেকর্ডের উপর কাজ শুরু করে, তখন system automatically সেই রেকর্ডটিকে অন্য সবার জন্য block
করে দেয়। এর মাধ্যমে নিশ্চিত করা হয় যে কোনো নির্দিষ্ট সময়ে শুধুমাত্র একটি write operation সম্পন্ন হতে পারবে। এই পদ্ধতিটি বিশেষ করে সেই সব
ক্ষেত্রে অপরিহার্য যেখানে তথ্যের সামান্যতম ভুলও বড় ধরনের আর্থিক বা logical বিপর্যয় ডেকে আনতে পারে। system-এর internal logic check
এবং যথাযথ validation প্রক্রিয়াগুলো সঠিকভাবে সম্পন্ন করার জন্য এই locking mechanism-টি একটি strong base হিসেবে কাজ করে।

2. Long Transactions
Complex Operations বা User Interactions-এর কারণে যখন transaction-গুলো অনেকক্ষণ পর্যন্ত lock ধরে রাখে, তখন pessimistic
locking data inconsistencies প্রতিরোধ করতে পারে। এটি mainly কাজ শেষ না হওয়া পর্যন্ত resources গুলোকে পুরোপুরি lock করে রাখে
যা data accuracy নিশ্চিত করে।
