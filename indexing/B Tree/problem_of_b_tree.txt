1. একটি ক্লাসিক B-Tree তে প্রতিটি নোডে (node) শুধু key নয়, বরং key এবং value দুটোই সংরক্ষণ করা হয় — এমনকি internal node গুলিতেও।
ডেটাসেট বড় হতে থাকলে এটি সমস্যা তৈরি করে।

- মেমোরি অপচয়:
যখন value বড় আকারের হয় (যেমন UUID বা row-pointer), তখন internal node গুলোতেও সেই বড় ভ্যালু জমা থাকে।
এর মানে হলো একটি পেজে কম key-value জোড়া রাখা সম্ভব হয়।

- কম key per page ⇒ বেশি পেজ:
একটি পেজে যত কম key-value জোড়া ফিট হবে, তত বেশি পেজ তৈরি হবে।

- বেশি পেজ ⇒ বেশি ডিস্ক রিড ⇒ পারফরম্যান্স কম:
বেশি পেজ মানে ডিস্ক থেকে পড়ার কাজ বাড়বে, ফলে পুরো সার্চ প্রক্রিয়া ধীর হয়ে যাবে।

2. B-Tree-এর আরেকটি বড় সীমাবদ্ধতা হলো range query হ্যান্ডল করা। ধরুন আপনি ডাটাবেসকে জিজ্ঞেস করলেন:
    “ID 4 থেকে 9 এর মধ্যে সবগুলো row বের করো।”

- B-Tree-এ sequential access-এর জন্য কোনো বিশেষ অপ্টিমাইজড পথ নেই। এর মানে, ওই range-এর প্রতিটি key খুঁজতে হলে আলাদাভাবে root
থেকে শুরু করে leaf node পর্যন্ত নতুন করে traversal করতে হতে পারে। যদিও ডেটা বাস্তবে ডিস্কে একটার পর একটা (contiguously) থাকতে পারে,
তবুও B-Tree এর গঠন আপনাকে সেগুলো সহজে ধারাবাহিকভাবে পড়তে সাহায্য করে না।

- B-Tree → point lookup (একটা নির্দিষ্ট key খোঁজা)-তে দারুণ কাজ করে। কিন্তু range scan (ধারাবাহিক মান খোঁজা)-তে কষ্ট হয়।

3. ডেটা ছড়ানো আর অগোছালো হয়ে যায়
- B-Tree যেভাবে insert হ্যান্ডেল করে — বিশেষ করে random key দিয়ে insert করলে — ডেটা খুব সহজেই ছড়িয়ে ছিটিয়ে যায় (scattered)।
- প্রতিবার নতুন data insert করার সময় যদি কোনো page পূর্ণ হয়ে যায়, তখন সেটি split হয়ে দুই ভাগে ভাগ হয়।
- এর ফলে নতুন যে row ঢুকল সেটি আগের কাছাকাছি না থেকে একেবারে অন্য কোনো branch-এ চলে যেতে পারে।

> ফলাফল:
  - ডেটা আসলে লজিকালি sequential হলেও (যেমন একটার পর একটা id), B-Tree structure-এর কারণে ডেটা ডিস্কে ছড়িয়ে থাকে।
  - এভাবে ছড়ানো ডেটা পড়তে গেলে অনেক I/O operation করতে হয়।
  - তাই sequential ভাবে পড়ার গতি কমে যায়।

-> B-Tree-এর এই সীমাবদ্ধতাগুলো দূর করার জন্যই B+ Tree এসেছে। এটি দুটি বড় সমস্যা (memory efficiency + range query) সমাধান করে—
- শুধু leaf node-এ value সংরক্ষণ করে। Internal node-এ কোনো value থাকে না, কেবল key থাকে।

- Internal node-গুলোকে হালকা (slim) রাখা হয়। Internal node-এ শুধু key থাকে, তাই এক পেজে অনেক বেশি key ফিট হয়। এর ফলে
tree height কমে যায় এবং lookup দ্রুত হয়।

- Leaf node-গুলোকে linked list-এর মতো যুক্ত করা হয়। Range scan করতে হলে প্রথম leaf node থেকে শুরু করে সহজে একটার পর একটা
sequentially traverse করা যায়। আলাদা আলাদা node এর জন্য root থেকে traversal করতে হয় না।

-> B+ Tree : Write বনাম Read পারফরম্যান্স
- write/insert এ একটু সময় বেশি লাগে, কারণ leaf node-গুলোর মধ্যে linked list maintain করতে হয়।

- কিন্তু read/query তে high speed পাওয়া যায়, বিশেষ করে range query-তে।

- ডাটাবেসের প্রধান কাজ যেহেতু read-heavy, তাই অধিকাংশ DBMS B+ Tree ব্যবহার করে।
