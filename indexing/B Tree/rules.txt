1. Balanced Tree
  * All leaf nodes are always at the same level.
  * This ensures that searching from root → leaf always takes the same number of steps → O(log n) time.

2. Order of B-Tree (m)
A B-Tree of order m means:
  * Each node can have at most m children.
  * Each node (except root) must have at least ⌈m/2⌉ children.

This rule is there to keep the tree balanced and space-efficient. If we didn’t force a minimum, one side of
the tree could become too sparse, and searching would be slower. So, the rule ensures:
    * No node is too empty.
    * Keys and pointers are distributed evenly.
    * Tree height stays logarithmic (O(log n)).

3. Number of Keys
  * A node can contain at most m – 1 keys.
  * Each node (except root) must have at least ⌈m/2⌉ – 1 keys.

Suppose order m = 4.
    * Max children = m = 4.
    * Max keys = m-1 = 3.
    * Min children = ⌈m/2⌉ = ⌈4/2⌉ = 2.
    * Min keys = min children - 1 = 1.

When m = 1
    * Max children = 1
    * Max keys = 0
    * Min children = ⌈1/2⌉ = 1
    * Min keys = ⌈1/2⌉ - 1 = 0
B-Tree of order 1 is meaningless / invalid. The smallest practical B-Tree order is m = 2.

-> Smallest Valid Case (m = 2)
    * Max children = 2
    * Max keys = 1

Each internal node works like a binary search tree node (1 key splitting 2 subtrees). So a B-Tree of order 2
behaves like a balanced binary search tree.

4. Root Node Special Case
The root is allowed to have fewer keys:
  * Minimum 1 key if it has children.
  * Root may also be a leaf node (when the tree is very small).

5. Key Ordering
  * Keys inside a node are sorted in increasing order.
For a node with keys [K1, K2, …, Kn] and children [P0, P1, …, Pn]:
    * All keys in subtree P0 < K1
    * All keys in subtree P1 are between K1 and K2
    * All keys in subtree Pn > Kn

6. Search Path
  * Searching always starts from root and goes down to a leaf.
  * Since all leaves are at the same level, the path length is the same for every search.


In B-Tree each searching complexity O(log n).
