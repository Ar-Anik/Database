1. When use N+1:
- The database must parse, plan, and execute each query separately.
- If there are 1000 books → 1001 queries.
- Even if each author lookup is fast, doing it 1000 times adds huge overhead:
    * 1000 network round trips.
    * 1000 index lookups.
    * 1000 query optimizations.

# Main Query
SELECT id, title, author_id FROM books;

# N Query
SELECT id, name FROM authors WHERE id = 10;
SELECT id, name FROM authors WHERE id = 11;
SELECT id, name FROM authors WHERE id = 12;
...


2. When use JOIN:
- Database builds one execution plan.
- It can choose the best algorithm:
    * Nested Loop: For each book, quickly lookup author by primary key.
    * Hash Join: Load all authors into memory, then match books to authors efficiently.
- Only 1 parse, 1 plan, 1 query execution, 1 network trip.
- Much less overhead.

# 1 Join Query
SELECT b.id, b.title, a.name
FROM books b
JOIN authors a ON b.author_id = a.id;
